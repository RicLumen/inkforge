## 这是什么

这不是一个长篇写作工具，也不是一个题材库。

它回答的是短篇创作者最实际的问题：选什么 AI 才顺手、配什么 skill 才省事、提示词按什么结构写才不像 AI 味、写完发哪里才有人看。题材、脑洞、人物与世界观，仍然由你自己定——方法只解决“怎么写得快、写得像人、发得出去”。

核心是三线程写法：写作按构思给的方向写一批，评审按量表逐项打分，写作逐条改，改到评审说不用再改才进下一批。

## 统一格式，不设档位

一篇短文是超短还是中短，不影响它的格式和每章字数，格式在两档里是一样的。AI 也不擅长一开始就决定好最终字数，往往是写完之后才能看出来是超短还是中短，所以本项目只规定确定的部分，不在开始前硬定最终字数和档位。

- 单章五百到一千字，不要切得过碎，每章结尾留钩子
- 付费截断点按情节锚点定在全文 35%-55%，锚点是主角不可逆选择、核心真相揭开或主冲突升级到无法回头的那一刻，每批后用脚本核对位置
- 情绪基调全程不变，结构起承转合，写到自然收束为止
- 默认第一人称，中途尽量不换视角
- 节奏要快，形成冲突、解决、再出现新冲突的循环
- 减少无信息增量的场景、心理和外貌描写，减少形容词
- 标点、标题和规范用字按 SKILL.md 正文规则来

写完之后再分类，仅作参考：总篇幅大致六千到两万五千字为超短，大致两万五到八万字为中短。

## 快速开始

把 `short-story-skill` 文件夹放进你所用 AI 工具的 skills 目录，或在对话里直接把 `SKILL.md` 加三份角色提示词发给 AI，然后给它你的剧情方向，让它按批次跑三线程，不要先让它定死最终字数和档位。

skill 本质是 Markdown 流程，即使某个平台不支持原生安装，也能直接读着执行。

## 目录

```
inkforge/
└── short-story-skill/
    ├── SKILL.md                  # 主流程
    ├── skill.yaml                # skill 元数据
    ├── prompts/                  # 写作 / 评审 / 构思角色提示词与骨架
    ├── scripts/                  # 字数与截断点计数脚本
    ├── CHANGELOG.md              # 历史口径变更
    └── references/               # 评审量表、拒稿点清单、状态卡、背景转述等
```

## 常见拒稿点

这五条是评审量表里主线、节奏、钩子、描写四项的具体查法，不是另跑一遍的第二套量表：主线不清晰、矛盾冲突悬浮、整体节奏慢、场景心理外貌描写过多且无信息增量、钩子不足。开始前问用户要不要启用，启用时作为量表第 2、5 项查法，不启用时只按八项量表评。详情见 `short-story-skill/references/rejection-checklist.md`。

## 安装说明

- Claude：`SKILL.md` 开头已有 YAML frontmatter（`name`、`description`），可按 Claude 的 skill 机制识别触发；`skill.yaml` 是 Muse 用的元数据，两者并存，不冲突。
- 其他平台：把 `short-story-skill` 文件夹放进 skills 目录，或直接把 `SKILL.md` 加三份角色提示词贴进对话就能跑，评审首选独立子 agent 或独立会话，只给最终文本、状态卡和量表；没有子 agent 的平台本质是人工逐批把关。
- 字数：必须用 `short-story-skill/scripts/count_chapters.py` 实数，输入永远是累计全文，写作每批跑脚本、评审核对章数和输出，禁止凭感觉和模型自数；没有代码环境时用户本地跑脚本再贴回输出。

## 边界

- 本项目分享的是方法，不承诺收益；作者个人实测结果不代表读者能达到同样收益。
- 示例均为脱敏改写，不公开作者真实作品全文与账号信息。
- AI 生成内容请按发布平台规则做人工审校与原创性检查。
- 签约编辑专属的题材偏好、保底条件和审稿时效不作为通用标准，不写进主流程。
