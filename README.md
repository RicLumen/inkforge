## 这是什么

这不是长篇写作工具，也不是题材库。

它回答短篇创作者最实际的问题：选什么 AI 顺手、配什么 skill 省事、提示词按什么结构写才不像 AI 味、写完发哪里有人看。题材、脑洞、人物与世界观仍由你自己定，方法只解决“怎么写得快、写得像人、发得出去”。

核心是三线程写法：写作按构思给的方向写一批，评审按量表逐项打分，写作逐条改，改到评审说不用再改才进下一批。

## 统一格式，不设档位

短篇是超短还是中短，不影响格式和每章字数，两档格式相同。AI 不擅长预先定死最终字数，往往写完才能确定篇幅，因此本项目只规定确定的部分，不在开始前硬定最终字数和档位。

具体格式（单章篇幅与上下限、引言、每章钩子、截断点位置、基调、视角、节奏、标点与规范用字）以 `short-story-skill/SKILL.md`“正文规则”与“细则索引”为准，本 README 不重复数字，避免两处漂移。付费截断点按情节锚点定在全文 35%-55%，锚点是主角做出不可逆选择、核心真相揭开，或主冲突升级到无法回头的那一刻；截断点只在全篇写完后用脚本 `--final` 核对，逐批不判。

写完之后再分类，仅供参考，分类区间见 SKILL.md“不设两档”一节。

## 结构说明

- `short-story-skill/SKILL.md`：流程与索引——三线程分工、批次推进、循环与终止规则，细则只写指针，不展开。
- `short-story-skill/references/`：细则——软目标排锚点、字数计数办法、补字数规则、对话软警告、全篇状态卡核对、八项量表、状态卡、拒稿清单。
- `short-story-skill/prompts/`：写作、评审、构思角色提示词与骨架，关键数字为独立会话重复。
- `short-story-skill/scripts/`：计数脚本、文档自检脚本、计数脚本回归测试。
- `.github/workflows/check.yml`：每次推送自动跑文档自检与计数回归测试。

## 快速开始

把 `short-story-skill` 文件夹放进你所用 AI 工具的 skills 目录，或在对话里直接把 `SKILL.md` 加三份角色提示词发给 AI，然后给它剧情方向，让它按批次跑三线程，不要先让它定死最终字数和档位。

skill 本质是 Markdown 流程，即使平台不支持原生安装，也可以直接读取并执行。

```
    └── references/               # 细则：软目标、计数、补字数、对话警告、最终核对、量表等
```

## 常见拒稿点

这五条是评审量表里主线、节奏、钩子、描写四项的具体查法，不是另跑一遍的第二套量表：主线不清晰、矛盾冲突悬浮、整体节奏慢、场景心理外貌描写过多且无信息增量、钩子不足。开始前问用户要不要启用，启用时作为量表第 2、5 项查法，不启用时只按八项量表评。详情见 `short-story-skill/references/rejection-checklist.md`。

## 安装说明

- Claude：`SKILL.md` 开头已有 YAML frontmatter（`name`、`description`），可按 Claude 的 skill 机制识别触发；`skill.yaml` 是 Muse 用的元数据，两者并存，不冲突。
- 其他平台：把 `short-story-skill` 文件夹放进 skills 目录，或直接把 `SKILL.md` 加三份角色提示词贴进对话就能跑。评审首选独立子 agent 或独立会话，只给最终文本、状态卡和量表；没有子 agent 的平台本质是人工逐批把关。
- 字数：必须用 `short-story-skill/scripts/count_chapters.py` 实数，输入永远是累计全文，写作每批跑脚本、评审核对章数和输出，禁止凭感觉和模型自数；没有代码环境时用户本地跑脚本再贴回输出。

## 边界

- 本项目分享的是方法，不承诺收益；作者个人实测结果不代表读者能达到同样收益。
- 示例均为脱敏改写，不公开作者真实作品全文与账号信息。
- AI 生成内容请按发布平台规则做人工审校与原创性检查。
- 签约编辑专属的题材偏好、保底条件和审稿时效不作为通用标准，不写进主流程。
