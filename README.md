# short-story-skill

用评审、写作、构思三线程循环，写短篇的方法 skill，篇幅与章节规格按投稿指南第二部分“正文”来，不设两档。

## 这个 skill 是什么

它不是一个一键生成器，而是一套执行规格：写作按构思给的方向写一批，评审按量表逐项打分，写作逐条改，改到评审说不用再改才进下一批。这样长篇幅才不会在中途断线、跑偏、字数失控。

## 不设两档，只规定确定的格式

一篇短文是超短还是中短，不影响它的格式和每章字数，格式在两档里是一样的。AI 也不擅长一开始就决定好最终字数，往往是写完之后才能看出来是超短还是中短，所以本 skill 只规定确定的部分，不在开始前硬定最终字数和档位。

写完之后再分类，仅作参考：总篇幅大致六千到两万五千字为超短，大致两万五到八万字为中短，剧情单薄的建议一万字上下，整体建议三万字左右。一万字左右尽量十二章以内是参考，不是所有篇幅的硬上限，关键是不要切得过碎。

## 硬格式速览

引言无标题约一百五十字，允许在六十到两百字之间；正文单章五百到一千字，每章结尾留钩子；付费截断点在全文 35%-55%的位置；情绪基调全程不变；默认第一人称，中途尽量不换视角；节奏要快，形成冲突、解决、再出现新冲突的循环；减少无信息增量的描写和形容词；标点、标题和规范用字按指南第二部分来，交稿前校对错别字、“的地得”和病句，不要空行。

原先“每章约 200 字”的口径已按指南改掉，不再使用。指南没有给出对话占比的具体数字，所以对话占比不再是硬性评审项，评审只看对话是否推进信息。

```
    ├── stack.md              # 作者实测 AI 与 skill（待作者填写）

```

## 怎么用

把整个 `short-story-skill` 文件夹放进你所用 AI 工具的 skills 目录，或在对话里直接把 `SKILL.md` 加三份角色提示词发给 AI，然后给它你的剧情方向，让它按批次跑三线程，不要先让它定死最终字数和档位。

skill 本质是 Markdown 流程，即使某个平台不支持原生安装，也能直接读着执行。字数必须用 `scripts/count_chapters.py` 实数，写作和评审各跑一次。`SKILL.md` 开头的 YAML frontmatter 供 Claude 识别，`skill.yaml` 供 Muse 识别。

## 边界

本 skill 不替用户决定题材，不承诺收益，不含用户真实作品、账号与收入截图。收入证明只放在项目 README 里脱敏展示。签约编辑专属的题材偏好、保底条件和审稿时效不作为通用标准，不写进本 skill 的主流程。
