# 批次状态卡

这是三线程在批次间传递的唯一状态。评审用的“主线一句话”和“前面章节摘要”均由此提供，不来自写作角色。

## 谁负责

- **构思负责写和维护**：开局写第一版，每批结束后更新一次。
- **写作不写状态卡**：写作只写正文，不写摘要、不给评审递话，否则会破坏评审隔离。
- **评审不改状态卡**：评审只读卡、按卡评，有问题写在评审意见里，由构思在下一批更新时修改。

## 字段（缺一不可，写不下就缩短，不要空着）

- 主线一句话：主角要什么 / 阻碍是什么 / 失败了会怎样。
- 锚点描述：不可逆选择 / 核心真相揭开 / 主冲突升级到无法回头，具体是哪一件事。
- 锚点章号：软目标，可改，例如第 5 章；改了要在卡里写明改动。
- 锚点之后计划章数：每批由构思重估一次锚点之后还要写几章，记录在此；该数值比脚本公式预警更直接，一旦变动，总章数估计与锚点占比估计须同步调整。
- 软目标总章数区间（默认 ±10%，例如 12 章即 11–13 章，四舍五入取整），可改，不是硬定最终字数；区间越宽，可选锚点越少甚至无解，不要一开始就定太宽。
- 情绪基调：全篇不变的那一个基调。
- 视角 / 人称：例如第一人称，中途换视角只能放在截断点之后。
- 已写章节清单：引言 + 第 1 章……已写到第几章。
- 上一批摘要：不超过 3 句，只写已发生的事实，不写写作推理，不写构思方向。
- 时间线：已写章节覆盖的时间顺序，例如“第 1 章：三月初三白天；第 2 章：三月初三夜”，供量表第 6 项核对时间线。
- 人物状态：主要人物到目前为止的状态，例如“林晚：已知绣样有问题，尚未告诉任何人”，供量表第 6 项核对人物状态前后一致。
- 未收伏笔（累计清单，永不滚动丢弃）：所有已埋未收的线，一条一行，注明埋在哪一章；收线时在该行后标注“已收于第 N 章”，不要整条删除；早期批次的线即便摘要不再提及，也须留在这里。构思规则中“上一批有未收伏笔必须先处理”核对的就是此清单，而非上一批摘要。
- 拒稿清单：默认启用。

## 模板

```
主线一句话：
锚点描述：
锚点章号（软目标，可改）：
锚点之后计划章数（每批由构思重估）：
软目标总章数区间（默认 ±10%）：
情绪基调：
视角 / 人称：
已写章节清单：
上一批摘要（不超过 3 句）：
时间线：
人物状态：
未收伏笔（累计清单，收线后标注已收章号，不要删除）：
拒稿清单：默认启用
```

## 截断点怎么用这张卡

- 逐批只记录是否已写到锚点章；锚点占比预估见 `references/soft-target.md`，预估不是判定，判定只在全篇写完后进行。
- 全篇写完后，用状态卡上的锚点章号运行 `scripts/count_chapters.py 累计全文.txt --anchor-chapter N`，累计 = 引言 + 锚点章及之前各章，截断点在锚点章之后，占比须在 35%-55%。
- 占比偏离时，调整状态卡上的锚点章号或锚点前后批次的篇幅，并重新评审受影响的批次。
