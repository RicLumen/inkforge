# 字数计数办法

分步执行，一步都不能跳过：
  1. 输入永远是累计全文（引言 + 已写全部章节），不是只含本批的批次文件；只含第 5–8 章的批次文件默认会报错，想单独数一批就用 `scripts/count_chapters.py 批次文件 --start-chapter 5`。
  2. 每批写完都把累计全文存成文件跑脚本，把脚本输出附在交付里；计数口径不数章节数字编号和空行，含标点。
  3. 评审拿到本批最终文本、状态卡、脚本输出和量表，先核对脚本输出的章数是否与状态卡的已写章节清单相符、章数是否为 0 或明显偏少，再看字数；脚本报错或章数为 0 时必须先修输入格式，不能直接按字数放行。对话占比看本批，不看累计：跑累计全文时必须加 `--batch-from <本批首章>`，否则累计占比会掩盖本批零对话。
  4. 每一章、引言、每一批写完都必须跑脚本；单章字数：低于 500 字是警告项、不是自动不通过，超过 1000 字是硬线、必须拆章或重写，1001 字也算超范围，没有宽限带，见 `padding-rules.md` 和量表第 3 项。最终总字数写完再算、再分类，不要在开始前硬定。
  5. 无代码环境的退路：把累计全文交给用户在本地跑 `python3 scripts/count_chapters.py 累计全文.txt --anchor-chapter N` 再把输出贴回对话；如果连本地跑代码都不行，走 SKILL.md 三线程分工一节的“不用再改”未实数例外，不要假装已经实数。
  6. 截断点：草稿阶段脚本只给锚点累计字数和预估占比（见 `soft-target.md`），不给通过 / 不通过判定；全篇写完后用 `scripts/count_chapters.py 累计全文.txt --anchor-chapter N --final` 才给判定，必须在 35%-55%。
