## v0.4（2026-10-28，第三轮外部评审后；优先修第 1、2、4 条）

- 更正 v0.3 记录：v0.3 曾写“删除了 SKILL.md 里‘先查、不过不能通过’的硬门槛说法”，实际 SKILL.md 第 56 行仍保留“评审不能只按通用量表走一遍就放行，必须先对照这五条逐项过”，与开局可选直接矛盾。v0.4 已删除该段，改为“启用与否在开局问过一次就按那次执行，中途不改口径”。记录说改了、实际没改，比不写记录更糟，本条以本次核对为准。
- 截断点判定只在全篇写完后做：逐批写的时候不要用锚点比例做决定，锚点刚写完时它必然接近 100%（例如只写到第 4 章、锚点在第 4 章时输出 100.0%），之后才下降，逐批数字一律忽略；偏离时的调法是回头调整锚点前后已写批次或挪锚点，不是继续往后写。
- 开局软目标：构思在状态卡里定软目标总章数区间（例如 12 章 ±20%）和锚点章号（都可改），这是事前排布锚点的手段；软估算不等于硬定最终字数，前者允许后改，后者不允许。
- 锚点累计定义明确：锚点累计 = 引言 + 锚点章及之前各章，截断点在锚点章之后，锚点章本身包含在内。
- 脚本输入永远是累计全文：只含第 5–8 章的批次文件默认报错是设计如此，文档此前没写；新增 `--start-chapter N` 可单独数一批；无引言用 `# 1` 时首行不再被当成标题吞掉；支持“第1章 重逢”这种带章名的写法，章名不计入字数；无代码环境的退路写进 SKILL.md 和 README：用户本地跑脚本再贴回输出，跑不了时评审必须写明“未跑脚本，仅人工估算”。
- 锚点单点定义：完整定义只在 SKILL.md 正文规则里，conceiver、writer、skeleton、reviewer、量表第 2 项各只保留自己那一句，不再全文复制；writer 不再读到给构思的指令，reviewer 的输出句不再被整段打断。
- 根 README 漏改补齐：拒稿清单改为开局可选，评审输入改为最终文本 + 状态卡 + 量表，字数改为累计全文 + 评审核对；skill README 文件树补上 `scripts/`、`CHANGELOG.md`、`references/state-card.md`；两份 README 里“按投稿指南第二部分”改为“按 SKILL.md 正文规则”，指南读者拿不到的那份只作背景转述。
- 批次状态卡新增 `references/state-card.md`：主线一句话、锚点描述和章号、软目标总章数区间、情绪基调、视角、已写章节清单、上一批摘要、拒稿清单启用与否；由构思负责写和维护，写作不写，评审不改，解决“主线和摘要没人产出、让写作写又漏隔离”的问题。
- 适用范围收窄：frontmatter 的 description 和 SKILL.md 开头写明面向中文付费短篇平台（女频古言等场景），“的地得”、冒号加双引号、500–1000 字章、付费截断点都是该场景专属，英文短篇、纯文学短篇不触发、不硬套。
- 仍未解决（不假装已解决）：没有示例输出和完整运行记录；三线程循环的实际成本和效果仍无证据，按用户 2026-10-28 计划后面做 GPT / Gemini 对比测试时再补。

## v0.3（2026-10-28，第二轮外部评审后）

- 截断点锚点定义同步到 conceiver、writer、skeleton、评审量表第 2 项和 reviewer，不再只写在 SKILL.md 和 README 里；锚点=不可逆选择 / 核心真相揭开 / 主冲突升级到无法回头。
- 锚点核对改为两阶段：构思按情节节拍把锚点定在中段（约 35%-55% 的节拍处）；每批后脚本只作过程参考，全篇写完后用 `scripts/count_chapters.py --anchor-chapter N` 算锚点累计占全文比例，必须在 35%-55%。删除了“预估全篇比例”这种没说清来源的说法，脚本也没有“预估总字数”参数。
- 脚本加固：支持 1、第1章、第一章、1.、1、、# 1；章节号必须从 1 按顺序递增，否则当作正文并警告（警告只显示前 10 条）；未识别到任何章节时退出码 2 并报错，不再静默把全文当引言；“3 / 2 / 1”这种行不被当作章节号；首行 `# ` 标题不计入引言；每章标出在范围内 / 低于范围 / 超范围，并汇总超范围章数；新增 --anchor-chapter。
- 评审隔离修正：reviewer 输入改为本批最终文本 + 主线一句话 + 前面章节摘要（仅用于第 6 项连贯检查），不给写作推理，不给构思方向；无子 agent 平台上直白写明流程本质是人工逐批把关，每批必须用户本人确认。
- 拒稿清单改为开局可选：开始前问用户要不要启用，启用时作为量表第 2、5 项查法、不过不算通过，不启用时只按八项量表评；删除了“作者本人必查”和 SKILL.md 里“先查、不过不能通过”的硬门槛说法。（注：该条记录不准确，见 v0.4 更正，SKILL.md 第 56 行实际未删，直到 v0.4 才删。）
- stack.md、platforms.md 删除“待作者确认”指令，改为作者示例、不是使用前提；writer.md、skeleton.md 删除“遵守投稿指南第二部分”的悬空引用，改为遵守 SKILL.md 正文规则。
- 删掉了“写作和评审各跑一次、不一致以脚本为准”的说法：脚本是确定性的，防线是评审核对章数和输出、用户每批确认。
- 仍未解决（不假装已解决）：没有示例输出和完整运行记录；三线程循环的实际成本和效果仍无证据，需要作者提供脱敏示例或跑一次真实批次才能补。

## v0.2（2026-10-28，Claude 评审后修订）

- SKILL.md 增加 YAML frontmatter（Claude 用），同时保留 skill.yaml（Muse 用）。
- 截断点改为情节锚点定义：锚点是主角不可逆选择、核心真相揭开或主冲突升级到无法回头的那一刻，锚点位置用脚本在每批后核对是否在全文 35%-55%，不再要求开始前先算总字数。
- 评审隔离：首选独立子 agent 或独立会话评审，只给最终文本、主线一句话和量表；无子 agent 时评审只重读最终文本，用户每批确认放行；“不用再改”必须附八项清单和脚本输出。
- 字数必须用 `scripts/count_chapters.py` 实数，写作和评审各跑一次，禁止凭感觉和模型自数。
- 时代语感条件化：古言时查古言语感，其他题材查该题材时代语感，不适用标“不适用”不判不通过。
- 拒稿清单改为评审量表第 2、5 项的具体查法，不另跑一遍；作者本人必查，其他用户参考。
- 去个人笔记：执行文件不再出现作者与 AI 的对话史、原提示词、成品实测数字等私人内容。
- 统一截断点写法为 35%-55%，角色提示词重复关键规则是有意的（评审独立会话时可能没有 SKILL.md 上下文）。
- 去 AI 味清单接入评审量表第 5 项，修复旧标题。
- 栈与平台空项不再阻塞流程，改用正在运行的 AI 和用户自选平台。
